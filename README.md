# IP Address to Country Filter for Thunderbird

Thunderbird のメッセージフィルタに `Originating IP country` 条件を追加する MailExtension です。メールの `Received` ヘッダを調べ、送信経路の最も古い側から公開 IP アドレスを探し、同梱した DB-IP Lite データベースで国コードを判定します。イントラネットのプライベート IP アドレスは飛ばして、次の公開 IP を調べます。

メインのメール一覧には `送信元国` 列を追加します。列が見えない場合は、一覧ヘッダーの列選択ボタンから `送信元国` を有効にしてください。検索ダイアログの結果一覧では、Thunderbird の合成ビューの制約により列の値が表示されない既知の問題があります。

## ビルド

初回またはデータを更新するとき、DB-IP Lite のリリース年月を指定してデータベースを取得します。Country CSV は `ip_start,ip_end,country` の3列形式です。

```powershell
python scripts/update-db.py 2026 10
```

年月は例です。DB-IP Lite の利用可能なリリース年月を指定してください。インターネット接続はデータベース更新時だけ必要です。生成された `data/ip-country.json` は拡張に同梱され、実行時の国判定はオフラインで行われます。このデータベースとビルド出力は Git 管理対象外です。

```powershell
./build-xpi.ps1
```

作成された `dist/ipaddr2country.xpi` は開発用のパッケージです。開発中の動作確認では、アドオンマネージャーの歯車メニューから「デバッグアドオン」→「一時的なアドオンを読み込む」を選び、リポジトリ直下の `manifest.json` を指定してください。一時読み込みは Thunderbird の再起動で解除されます。通常版 Thunderbird に恒久インストールする XPI は署名が必要です。この拡張は実験 API を使うため、Thunderbird とコンピューターへの完全なアクセス権限を求めます。

## フィルタ条件

フィルタ条件で `送信元IPの国 (Originating IP country)` を選び、`is` または `isn't` と ISO 3166-1 alpha-2 国コード（例: `JP`, `US`, `DE`）を指定します。判定するIPが見つからない、またはデータベースにない場合は一致しません。

## 制約

- メールヘッダの `Received` は途中のメールサーバが追加する情報です。送信元IPが記録されていないメールや、信頼できるサーバが付けたヘッダを確認できないメールでは判定できません。ヘッダに記載された経路を厳密に検証する機能ではありません。
- 検索中にリモートのメールサーバへ同期アクセスしないよう、ローカルフォルダまたはオフライン保存済みのメッセージだけを検査します。IMAPのメッセージがオフライン保存されていない場合、そのメッセージは一致しません。最初の検索では各メッセージのヘッダを読み取るため、対象が多いフォルダでは時間がかかることがあります。判定結果はメモリ内にキャッシュされ、同じメッセージの再検索を短縮します。
- プライベート、ループバック、リンクローカル、予約済みアドレスは国判定せず、次の候補を調べます。公開IPから国を推定するため、データの精度やVPN・プロキシの利用によって実際の送信者の所在地とは異なることがあります。
- DB-IP Lite は月次更新の無料版で、商用版よりカバレッジと精度が低い場合があります。再配布時は DB-IP の帰属表示を維持してください。
- 実験APIはThunderbird内部APIに依存します。この初期版の最低対応バージョンは Thunderbird 128 です。
- アドオンを削除しても、保存済みフィルタに追加した国条件は自動削除されません。Thunderbirdの実行中はカスタム検索語の登録が残る場合があるため、削除後にThunderbirdを再起動してください。保存済みフィルタに残った条件は、フィルタ設定画面で行を削除してください。

## デバッグログ

Thunderbird の「ツール」→「開発ツール」→「エラーコンソール」で `IP Country Filter` を検索してください。オフラインDBの読み込み・変換時間、検索の進捗（1,000件ごと）、キャッシュ命中数、ヘッダ読込時間、国判定時間を出力します。メッセージごとのログは出さず、検索後に集計を出します。

カスタム検索語の `match` は同期の真偽値を返すThunderbird内部APIです。そのため、検索中に処理が同期実行されている間は画面のイベントが処理されず、停止ボタンがすぐ反応しないことがあります。停止に即応させるには、検索前の非同期インデックス作成などへ構成を変更する必要があります。
